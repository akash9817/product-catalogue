# Agent instructions

Guidance for AI coding agents working in this repo.

## Layout

- `backend/`: Node.js + TypeScript (Express 5, zod, nodemailer). Entry point `src/index.ts` is the only composition root.
- `web/`: React + TypeScript (Vite, React Router). Talks to the backend only through `/api`.
- `docker-compose.yml`: runs web, backend and Mailpit (local SMTP inbox).

## Architecture rules

- The web client must never call the Fake Store API (or any product data source) directly. All product data goes through the backend.
- Product data is accessed only through the `ProductSource` interface (`backend/src/products/ProductSource.ts`). Fake Store specifics stay in `FakeStoreProductSource.ts`.
- Email is sent only through the `EmailSender` interface. Do not import nodemailer outside `backend/src/email/`.
- Services (`backend/src/services`, `backend/src/enquiries`) must not import Express or `Request`/`Response` types.
- Routes validate input with zod and map errors with the classes in `backend/src/errors.ts`. The central error middleware turns them into JSON. Never send stack traces or upstream error text to clients.
- Keep the web's `api/types.ts` in sync with the backend response shapes.
- Category slugs are generated by `toCategorySlug` on both sides. Change them together.

## Commands

- Backend: `cd backend && npm install && npm test` (vitest), `npm run typecheck`, `npm run dev`.
- Web: `cd web && npm install && npm test`, `npm run build`, `npm run dev`.
- Full stack: `docker compose up --build`.

## Conventions

- TypeScript strict mode everywhere. No `any` unless there is a comment explaining why.
- Tests: every behaviour change needs a test. Backend tests live in `backend/test/`; web tests sit next to the component.
- Do not add paid services or accounts. Do not commit secrets. Configuration goes in `.env.example`.
- Keep changes small and in scope. Record any assumption you make in `DECISIONS.md`.
